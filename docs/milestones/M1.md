# M1 – Records, offline-first (plan, 2026-11-17)

Status: **APPROVED by Bora on 2026-11-17, with the changes from the team review** (`M1-inputs/m1-plan-review-agro.md` = AGRO, `m1-plan-review-tech.md` = TECH2). Bora's answers are in section 6.
Inputs used (advice, not decisions – the choices are written here): `M1-inputs/techlead.md` (TL), `product.md` (PM), `ux-qa.md` (UX), AGRO, TECH2. `accounts-security-review.md` is about the account step and is already applied to `RUNBOOK.md`.

## 1. Goal

Bora can record his real farm **on the phone, offline**: parcels, plantings, products with label uses, stock, soil/water tests (PM §1, stories S1–S3), and can **back everything up to a file** (photos included). Everything survives airplane mode and reload. No Supabase/Cloudflare account is needed for any PR except the last one (live sync).

## 2. Scope

**In (PM §1 "Week 1 required" columns, TL §1, plus AGRO/TECH2):**
- Parcel: name, **pin + typed στρ.** (map later, optional), soft-archive.
- Planting: parcel, crop chip, lot label, area στρ, sown_on, status.
- Product: trade name, reg. no., type, unit, label photo (stored on the phone).
- Label use (per product × crop): **dose kind (single / range) and dose unit, both mandatory choices**, PHI d, REI h, max apps, source, and a **target (pest/disease) field in the data model from day one** (not mandatory in M1, mandatory before M2). Each value is *empty / entered / "δεν αναγράφεται"*. Sign-off badge «Μη εγκεκριμένο».
- Stock: lots (batch, expiry with year, qty) and a movements ledger. Corrections are new rows, never edits or deletes.
- Soil/water test: date, lab, report photo, pH, EC (rest optional).
- **Photos:** each photo is a row with UUID + sha256 and enters the outbox now, so it uploads by itself once Supabase exists.
- **JSON backup and restore, photos included**, with "only on this phone · last backup: …" shown in the app (highlighted when older than 7 days or never done) (AGRO §2).
- **Standalone / persistence warning:** a banner when the app is not added to the Home Screen or `persist()` is refused (TECH2 §1.5).
- Local schema v2 (UUID ids, snake_case, `farm_id`), one write path with an outbox, `apply_ops` + pull SQL tested on CI Postgres.
- Guardrails and UX gates in CI (section 4).

**Out (PM §4, plus additions):** spray/harvest logging and stock decrement by jobs (M2); PHI/REI countdowns; weather, rules, notifications (M3/M4); worker accounts, costs, Κλούβες sync, sensors; OCR / any auto-fill of label values; prefilling labels from the prototype or "typical" doses; unit conversion of any kind; map drawing or ΟΣΔΕ code as a requirement to save a parcel; structured golden fixtures (move to the start of M3); applying any migration to Supabase.

## 3. Decisions (each also in `docs/DECISIONS.md`, dated 2026-11-17)

1. **Doses are decimal strings** exactly as typed, stored canonical (`0.025`), shown Greek (`0,025`). No `number` for label values. Comparisons (min ≤ max) use scaled-integer BigInt. No rounding anywhere on this path (TL §2, QA P0-1).
2. **Decimal input never guesses (TECH2 §1.3).** Greek decimal separator is the comma. Accepted: `0,025`, `0.025` (integer part 0, so unambiguous), `12,5`, `12.5`. **Rejected as «μη έγκυρο»:** a single separator followed by exactly three digits when the integer part is not 0 (`1.000`, `1,000`), two or more separators, or both kinds (`1,000.5`). Golden tests for all four cases from TECH2.
3. **Dose form (Bora, answer 1; replaces the earlier "dose_max only" idea):** the label-use form first requires a choice **Μία δόση (single) / Εύρος (range)**, nothing preselected, no save without it. *Single* → one box, stored `dose_kind='single'`, `dose_min = dose_max = typed value` (Bora chose "single", so this is not a silent default). *Range* → two boxes, both required, `min > max` is rejected. **Unit is a mandatory choice, no default** (list is **provisional**, Bora will finalise it from photos of his labels): per στρέμμα `ml/στρ.`, `g/στρ.`, `L/στρ.`, `kg/στρ.`; per 100 L of water `ml/100 L νερό`, `g/100 L νερό`. The unit and value on the label are stored exactly as written: **no conversion and no rounding, ever** (not even ha → στρ.). No unit chosen → *Blocked*. **If a label shows a percentage (%) or a unit that is not in the list, do not add it: ask Bora.** Empty or «δεν αναγράφεται» → *Blocked*. **The Demo farm follows the same rules:** the prototype dose is imported as `single` and keeps the «Μη εγκεκριμένο» badge; the prototype's unit text (`L/στρ`, `kg/στρ`, …) maps to one of the listed units only if it matches exactly, otherwise the unit stays unset (= Blocked).
4. **Branded types:** `DosePerStr`, `PhiDays`, `ReiHours`, `MaxApps` only come from `parseLabelValue()` returning `Known<T>` (`known:false` = blocked). Deciding functions accept only `SignedLabelUse`, produced only by `requireSignOff()`. Sign-off stores agronomist name + date + a **hash of the label values** (dose kind, unit and target included); any edit changes the hash, so the sign-off drops automatically (PM §2).
5. **Ids:** every row has a UUID. Demo rows get **UUIDv5** from a fixed namespace + the prototype id (`P1` stays as `legacy_id`); done once, in PR 4a, so references are not rewritten twice (TECH2 §1.1). The `uid = farmId:id` key is removed (TL §4.2).
6. **Old database:** the new DB is `aloni`. The old `aloni-farm` DB is deleted **only if every row in it belongs to the Demo farm**; otherwise it is kept and the app offers a JSON export first. Tested (TECH2 §1.2, AGRO §3.3).
7. **One write path (TECH2 §1.4):** `repo.put()` writes the row and its outbox entry in one transaction. ESLint bans Dexie writes (`put/add/bulkPut/update/delete/clear`) outside `src/repo/`; a Dexie hook **throws on update/delete of append-only tables** (spray, harvest, stock movements, fertilise/irrigate/sow, observations, media). **Where the audit trail lives:** amending rows + the outbox (kept ≥3 years) locally, `audit_log` on the server. The **Demo farm never writes to the outbox.**
8. **actor vs device (Bora, answer 2):** every outbox op and every append-only record carries **both** `actor_id` (who did it) and `device_id` (which phone), kept separate from the start. Whether workers use their own phones or a shared farm phone is **undecided; Bora decides before M2**. Both stay possible. (TECH2 §4 suggests "shared phone + PINs" as a default; that is advice only.)
9. **Photos (Bora, answer 4):** Blobs in IndexedDB, downscaled to ≤2000 px on the long edge, each with UUID + sha256 and an outbox entry. Included in the JSON backup. App warns "only on this phone · last backup …"; stronger if >7 days or never. iPhone checklist **step 1 = "Add to Home Screen"**.
10. **No confirm dialogs.** Save at once, show a 5 s «Αναίρεση» toast. Delete = archive (`deleted_at`) with undo; append-only data gets «Διόρθωση» (UX §1).
11. **Map:** "Pin + type στρ." ships first and is the only path in Bora's checklist. MapLibre/Terra Draw/turf comes behind one `TILE_SOURCE` config pointing at OSM **for development only**. Provider decision is open: comparison and a Greek email draft to Ktimatologio come as a separate docs PR (`docs/milestones/M1-map-providers.md`); until Bora decides, the pin + στρ. path is enough.
12. **Environment (not code):** the single-branch shallow clone made the "unpushed commits" hook warn falsely. Fixed once with `git config remote.origin.fetch '+refs/heads/*:refs/remotes/origin/*'`; new branches go out with `git push -u origin HEAD`. Written into `CODING_STANDARDS.md` and the RUNBOOK developer notes.
13. **Live sync** (HTTP calls to Supabase) is the last PR and needs the accounts. Until then the app shows «N μη συγχρονισμένα» honestly.

## 4. Guardrails and gates (TL §2, UX §2)

- `CODING_STANDARDS.md`: every safety rule in `CLAUDE.md` paired with the mechanism that enforces it, plus the git notes (decision 12).
- **ESLint in CI:** ban `Math.round/floor/ceil`, `toFixed` and `?? <number>` in label/dose/spray code and `rules-core`; ban `Date.now()/new Date()` in `rules-core`; ban JSX text / string literals outside `t()`; require `no-floating-promises`; from PR 4b, ban direct Dexie writes outside `src/repo/`.
- **Vitest:** el/tr/en key parity, every used `t()` key exists and no dead keys, `{n}` placeholders match, Greek decimal golden cases (decision 2), `formatDose('0.025') === '0,025'`, missing dose renders «—  άγνωστο», single/range/unit validation, demo-isolation (outbox stays empty), guarded deletion of the old DB, append-only throw, `rules-core` has its own test command.
- **Playwright WebKit 375×667:** `iphone()` helper; `ux-bar.spec.ts` (no horizontal scroll; every button/link/input ≥56 px high and ≥44 px wide; every visible text ≥14 px) for every route × el/tr/en incl. empty states; **axe** (serious/critical fail); offline flow; undo flow with no `dialog` event; backup export → wipe → restore round trip; screenshots per route × language × (normal/empty/offline), **always uploaded** as artifact `screens-<PR#>`.
- **PR template:** safety rules touched? · el/tr/en · 375 px e2e · DECISIONS · Turkish note · the 7-step Greek iPhone checklist with "Add to Home Screen" as step 1.

## 6. Bora's answers (2026-11-17)

1. **Dose:** no "same number in two boxes". First a required choice *single* or *range* (nothing preselected); single = one box (`min=max`, chosen by Bora, not a silent default); range = two required boxes, `min>max` rejected; unit is a required choice (6 units, provisional; see decision 3), no conversion; target field in the model now; Demo follows the same rules. → decision 3.
2. **Worker phones:** not decided; Bora answers before M2. `actor_id` and `device_id` separate from the start. → decision 8.
3. **Map:** write the comparison (offline cache licence, free quota and commercial use, imagery date/quality over Megara, EU hosting, attribution) and add Ktimatologio with a short Greek email draft. Until decided, "pin + type στρ." is enough. → decision 11 (separate docs PR).
4. **Photos:** phone-only is accepted **with** JSON backup/restore (photos included), a visible "only on this phone / last backup" warning (strong after 7 days), photos queued with id + sha256 for later upload, and warnings for non-Home-Screen / refused persistent storage; checklist step 1 = Add to Home Screen. → decision 9, PR 7.
