## Is the single gate the only calculation? (server side: yes)
- In the final DB, the functions that read `phi_until`/`rei_until` or `phi`/`rei` are:
  - the gate itself
  - its three consumers: `check_harvest_phi`, `complete_spray_job`, `harvest_conflicts_rows`
  - `check_spray_record` (corrections), through `spray_floor` → `spray_floor_crops`
  - the label triggers `normalize_label_row` and `forbid_used_label_change`
- `spray_floor_planting` is dropped (0032:154), and no function body references it. No view other than `harvest_conflicts` reads `job_spray`.
- **Corrections do not call the gate.** `check_spray_record` uses `spray_floor_crops` only to validate a *typed* value (it must be at least the label, and every crop needs a label). That is acceptable on the server, because the gate never lets a typed or stored value *open* anything. Typed and stored values can only close (0032:14–15). They also cannot be shortened: a correction can never make `sprayed_at`, `phi_until` or `rei_until` earlier. See S-NEW-1 for the gap.
- **The client is a second, independent calculation.** It is outside this PR's diff, but it is the same class of bug:
  - `app/src/spray/harvest.ts:14–35` `harvestGate` computes PHI/REI from the spray row's **stored** `phi_days`/`rei_hours`, not from the planting's own crop's signed label.
  - It feeds `HarvestForm.tsx:37`, the cut list (`summary/cutlist.ts:28`), the order supply (`orders/available.ts:26`) and the worker's REI lock (`WorkerApp.tsx:70`, `reiLockJob`).
  - See S-NEW-1.

## New findings

**MUST: none in 0032.**

**S-NEW-1. SHOULD (fix before the real-farm cut list or order availability is relied upon; the SQL part is one line and can go into 0032 now): the phone can show a planting as harvestable or enterable while the server gate says closed. An actual harvest can then go unrecorded.**
- **Server side, 0032:144–148:** the `applies` set in `spray_floor_crops` has **no `l.sign_off_by is not null`**. So a crop whose only label is an *unsigned* draft with values still satisfies "missing = 0", and a typed PHI/REI is accepted.
  - Repro as the owner: crop Z has only an unsigned draft (PHI 1 / REI 1). The typed PHI 3 / REI 24 on the Z+Y spray is **accepted** (INSERT 0 1). The server harvest gate stays closed, which is correct.
  - This lets an unsigned label decide whether a value is accepted (safety rule 3). It also syncs a typed period to every phone.
- **Client side, `harvest.ts:14–35`:** the phone trusts that typed row, and the same goes for legacy cross-crop rows. On day 4 it shows Z as open in the harvest form, in the cut list and in the supply. The insert is refused only at sync time, so a cut that has already happened is never recorded, and it never appears in `harvest_conflicts`.
- `buildWaitEntry` (`spray.ts:127–137`) lets the owner type any PHI offline, with no label check.
- Fix:
  - **(a) In 0032:** add `and l.sign_off_by is not null` to `applies` in `spray_floor_crops`.
  - **(b) Separate app PR:** make `harvestGate` and `reiLockJob` follow the server's rule. Use the planting's own crop's signed label for the product, take the max with the stored end, and treat unknown as closed. Add a golden test shared with m13, for example the legacy X+Y row and the unsigned-draft Z case.
  - **(c) RUNBOOK §15:** keep "rows → do not apply" as it is. Today this read-only query is the only thing that catches the legacy rows that hit the client.

**S-NEW-2. SHOULD (operational, fails closed): the new token will probably never reach the function.**
- Supabase Edge Functions verify a JWT at the gateway by default. The repo has no `[functions.weather-fetch] verify_jwt = false` in `supabase/config.toml`, and no `--no-verify-jwt` in `weather-deploy.yml:106`.
- The old service key was a JWT, so it passed the gateway. A random 32-character `WEATHER_CRON_TOKEN` will very likely get 401 "Invalid JWT" before `index.ts` runs. That applies to the cron call and to the RUNBOOK §14 step-2 dashboard test. I could not verify this against a real project from here.
- Fix:
  - Deploy with `--no-verify-jwt`, or set `verify_jwt = false` for this function. The function does its own token check.
  - Or send the anon key as `Authorization` and the token in a separate header, such as `x-cron-token`.
- Also in RUNBOOK §14:
  - Step 2 uses the token, but the token is only created in step 4a/4b. Move 4a/4b before step 2.
  - Step 1 still says "ek bir gizli anahtar gerekmez … servis anahtarını". That is stale.

**S-NEW-3. SHOULD (needs an agronomist decision; the behaviour is old, not new in 0032): the «Έγινε» REI lock checks at the *end* of the spraying, not at its *start*.**
- 0032:82 calls the gate at `p_ended_at` and `now()`, but the worker was in the field from `p_started_at`.
- Repro as b2:
  - The earlier REI on the planting ran until now−10 min. b2 sprays from now−30 min to now−1 min.
  - The call **succeeds with `flags: []`**: 20 minutes inside the REI, with no `rei_conflict` flag.
- Fix: also evaluate the gate at `p_started_at`. At the least, add the `rei_conflict` flag. If live, refuse, unless the agronomist confirms that the applicator in PPE is exempt; then record that in DECISIONS.

**LOW**
- **LOW-1, 0032:197:** in LIKE, `%` matches any characters, including `/` and `?`. So `https://evil.example/?.supabase.co/functions/v1/weather-fetch` passes the "host check". Only the owner writes to Vault, and the token is now narrow, so this is defense in depth. Use `~ '^https://[a-z0-9]{20}\.supabase\.co/functions/v1/weather-fetch$'`.
- **LOW-2, `harvest_conflicts` ACL:** `authenticated` has `arwd` on the view (from default privileges). 0032:133 only adds SELECT. The view cannot be updated, so this is harmless. For clarity: `revoke insert, update, delete on harvest_conflicts from authenticated`. The Supabase linter will also flag a security-definer view; `security_invoker = true` would be fine here, because the function does the filtering.
- **LOW-3, `harvest_conflicts_rows` performance:** it runs the gate for every harvest of every farm, then filters by role (0032:121–124). This is fine for Phase 1, but filter on `farm_id in (the caller's farms)` before the lateral before the pilot.
- **LOW-4:** the headers of 0030:5 and 0030:16 still describe `weather_service_key`. 0032 replaces the schedule, and the RUNBOOK no longer creates that secret. Only the comment is stale. Add one line to DECISIONS saying that 0030's key path is superseded.
- **LOW-5, `index.ts` `sameText`:** it leaks the length through `x.length ^ y.length` and the loop bound. This does not matter with a fixed 32+ character secret.
- **Checked OK:**
  - Every SECURITY DEFINER function in `public` and `private` has a fixed `search_path = public, private, pg_temp`, with `pg_temp` last. The query for any without one returned 0 rows.
  - No SECURITY DEFINER function grants EXECUTE to `PUBLIC` or `anon`.
  - `private.planting_gate` and `lock_job_before_spray` are revoked from public, anon and authenticated. `harvest_conflicts_rows` is EXECUTE for `authenticated` only.
  - anon has no USAGE on `private`.
