# Independent review of 0037 owner records

Design [#364](https://github.com/seaevill/Aloni/pull/364), implementation [#368](https://github.com/seaevill/Aloni/pull/368) at `1b2e4a7`.

## MUST

1. **Preserve tenant ownership across parent updates.** `supabase/migrations/0037_owner_records.sql:28–45,57–68,84–90`. The customer reference uses a single-column foreign key, and the tenant comparison only runs when an order itself changes. The policy and grant leave the customer's farm column editable to a user who owns both farms. An existing order can therefore retain a parent in another farm. Enforce same-farm identity with composite foreign keys and prevent tenant reparenting on owner records. Extend this invariant to the worker and crop references and test with an owner of two farms.
2. **Make the sync definition precondition enforce the promised compatibility.** `supabase/migrations/0037_owner_records.sql:5–11,93–151`. Checking for one table-list fragment per function does not establish that the existing security mode, cursor handling, or authorization logic is the revision this file will overwrite. Validate the exact supported predecessor definitions or isolate the table-list change in a separately versioned contract. Test a modified predecessor that retains the marker.

## SHOULD

- `supabase/tests/m17_owner_records.sql:35–46` tests a same-farm worker. The comment about an owner of another farm has no corresponding session or assertion. Add a distinct authenticated cross-farm identity and exercise read, pull and rejected write at the public sync entry points.
- `supabase/migrations/0037_owner_records.sql:57–68` uses a security definer in the exposed schema, with execution revoked. Put the trigger helper in the private schema, qualify the relations and use a minimal fixed path. The current revoke and owner RLS predicates in lines 81–86 are necessary and should remain covered.

Check archived parent behavior in the UI contract. The reference checks at `supabase/migrations/0037_owner_records.sql:61–64` accept an archived parent. Existing history needs to remain readable, while creating new orders against archived customers needs an explicit contract.
